# Architecture Overview

Describe how the system currently works, its important boundaries, and active
contracts, using the repository's current source of truth.

- Follow the repository's documentation convention. If no architecture
  location is defined, use `docs/architecture/`.
- State scope and purpose; describe main components, ownership boundaries,
  and data flow.
- Link contracts, schemas, APIs, CLIs, or artifact definitions that callers
  rely on.
- Summarize key decisions that still affect implementation and link decision
  records when they exist.
- Distinguish current behavior from proposals and historical behavior.
