# Grok 配置对照完成：本批未显示更贴合人工反馈

使用 Pi 1.5.0 的 `xai / grok-4.7 / high` 配置，与当前
`openai / gpt-6-sol / high` 比较，八次调用均得到有效报告。没有经过此前的 OpenRouter
provider 配置，也没有修改凭据。这里确认的是所选 Pi 配置本轮可调用，不推断其他路由
可用性，也不声称核实了底层服务或网关的全部配置。

本批不支持替换为 Grok。它识别了重复与辩解，也保留了有用机制，但未解决人评关注的
共有内容必要性问题，并增加了一项过于确定的术语批评。没有自动胜负或整体模型排名。

## 设计与执行

冻结提交 `adbd967`；复用既有执行器，没有新增代码。语义准则、段落编号引用、四份
问题与回答、Markdown 和调用控制均与前轮相同。每份回答的两模型请求记录中，
system/messages 完全一致；人工标签和组名不进入请求。

- D02-A、P02-A 先调用 Grok，D05-A、D06-B 先调用当前模型；第一调用计入预算。
- 完成 targets 后，先写 [阶段审阅](review-targets.json)，再执行 preservation。
- 无重试、修补、结果后调提示、模型切换或追加调用。旧 Claude/Gemini 失败保持原样。

[协议](protocol.json)、[材料与顺序](jobs.json)、[冻结摘要](manifest.json) 可核对上述边界。
Provider 与模型一起变化，high 不保证相同计算量，因此比较对象是两套配置。
四份材料均是作者已见的旧回答，不是四组完整 A/B 题对或独立 holdout。

## 具体观察

| 回答 | 当前模型 | Grok | 本批判断 |
| --- | --- | --- | --- |
| D02-A | 指出“97%”重复，仍肯定常见误解纠正 | 同样指出重复并肯定纠错，另批评术语与“所以”的连接 | 未解决未问纠错的必要性分歧 |
| D05-A | 指出辩解末段多余，肯定共有解释 | 判断相近 | 未识别用户认为多余的个人行动共有句 |
| P02-A | 认可净蒸发机制与散热联系 | 认可机制，另解释各环节及限定语的作用 | 两者均保留有用机制，未见此例退步 |
| D06-B | 肯定双方关注点和感受可以同时成立 | 还明确肯定“不必比谁更委屈”的结尾 | 两者均未识别目标铺垫、比喻及冗余结尾 |

Grok 在 D02 把“检验假设”视为歪曲 p 值定义的额外条件。该措辞可能指检验前提，
也可能引起其他理解；Grok 没有说明其解释为何成立，却作出确定批评。审阅保留这项
过度确定/依据不足风险，没有据此认定原文已被证明存在概念错误。因语义歧义尚未解决，
未把它直接计为已证实的重大错误，随后仅执行原定保留检查。

Grok 对 D06 结尾的肯定尤其值得保留：它认为删去会失去沟通连接，但人评明确认为
该结尾多余。指出某句有可描述的作用，仍不足以证明用户在此处需要这句话。
这是人机分歧，没有改成人工认可，也不自动授权保留或删除。

Grok 的更多 finding 不构成优势；P02 的细分说明也不能替代更广泛的保留验证。
[第二阶段及总体审阅](review-preservation.json) 由实施助手完成，未盲化。
