## 改动边界

[引用适配器](../openevals_id_evidence.py) 复用原对照执行器、OpenEvals 组件、模型、
隔离调用、失败留存和单次尝试控制。没有修改组件源码、旧执行器或旧失败。

原版与修订版都使用新的 `paragraph-id-v1` 引用契约：

1. 目录按空行划分非空原文段落，以 P1、P2 等编号；保留段落内部空格、换行与 Markdown。
2. 模型输出的 `evidence` 是一个精确编号，schema 增加本题编号枚举；system 只替换
   引用指令，user 消息追加引用目录。问题与待评回答原文不变，目录不含人工标签。
3. `transport.answer` 保留原始可见模型输出，`id_diagnostic` 保留原始解析结果；
   `diagnostic` 的引用由程序按目录提取，并再次通过原逐字引用校验。
4. 未知编号、前后空格、前缀匹配、拼接编号及直接复写原文均拒绝。不猜编号、不修补、
   不提取部分有效 finding、不自动重试。记录保留原文 SHA256，目录保留 Unicode 字符偏移。

这是新的模型输出契约。字段形状仍为 kind/evidence/reason，但 evidence 的含义改变，
不能把派生引用说成模型逐字写出的文字。语义准则文件与上一轮逐字节相同；引用目录、
格式指令和 schema 的变化仍可能影响判断，因此两轮不能视作相同实验直接合并。
原提示授权仍见 [MIT 文件](../openevals-pilot-1/upstream-LICENSE.txt)。

段落定位比短语引用粗。D06 两份回答都只有一个段落，所有引用均为 P1；编号有效只证明
能定位原文，不证明理由正确、相关或充分。程序不将模型的判断替换成人工标签。
