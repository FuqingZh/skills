# 内容贡献准则 v1：局部变化，迁移检验因引用失败停止

本轮只给 OpenEvals 的原 helpfulness 提示增加三项内容贡献准则，没有 fork 或修改
组件源码、模型、system 指令或输出 schema。冻结提交 `4951a46`；结果后没有改提示。
新增文字见 [guidance.txt](guidance.txt)，完整提示见
[revised-helpfulness.txt](revised-helpfulness.txt)。原提示及
[MIT 授权](../openevals-pilot-1/upstream-LICENSE.txt) 保持原样。

## 对照设计

- 使用同一 `openai/gpt-6-sol`、high、Pi 1.5.0、隔离配置和单次尝试规则。
- 原提示也重新调用，历史报告不替代本轮对照。各回答轮换原提示先、修订提示先的
  顺序，输出后不换序重跑；每次调用独立，不向模型暴露人工标签或实验组名。
- 目标检查：D02-A、D05-A；保留检查：P02-A 的机制、P03-B 的持续功率条件。
  这是四份选定回答，不是四组完整 A/B 题对。
- 迁移探针：已有人工标签、作者可见的 D06-A/B，当前 OpenEvals 此前未评过。
  它不是独立 holdout。作者审阅未盲化，每臂每份回答只取一次结果。
- 最多 12 次调用，阶段间审阅；任何调用或引用契约失败即停，不修补、重试或扩展。

用统一入口 [openevals_compare.py](../openevals_compare.py) 读取冻结的
[protocol.json](protocol.json) 和 [jobs.json](jobs.json)。原评审器从临时提示目录读取
选定模板；schema 与 system 文件按原字节复制，调用结束后恢复目录并清理临时文件。
模型请求记录包含实际使用的完整提示。后续同类对照可复用入口，无需再写逐题执行器。

## D06 迁移检验未完成

D06-A 原提示得到一份有效报告；修订提示传输成功、JSON 可解析，但首项 evidence
不是连续原文，校验返回：

```text
ValueError: Evidence absent from answer
```

模型引用跨过了 Markdown 加粗的结束边界：

```text
原文：临时取消确实影响了我”。** 这两件事可以同时成立。
引用：临时取消确实影响了我”。这两件事可以同时成立。
```

它漏掉了 `**` 与其后的空格。按冻结契约，这份报告无效，不能把其他 finding 捞出
并计作有效。保留完整可见输出、用量及费用，没有补符号或重新调用。D06-B 两臂均未
执行。原记录见 [baseline](results/D06-A/baseline.json)、
[revised](results/D06-A/revised.json) 与 [停止审阅](review-transfer.json)。

因此迁移效果未知；引用失败也不能单独证明修订提示造成语义退步或更高的失败率。

## 结论与后续边界

保留修订为实验候选，不替换原提示。当前仅观察到一处期望的重复诊断，两个机制/
条件保留案例未见退步；另外两个必要性分歧仍在，迁移结论缺失。没有自动胜负、
偏好准确率、整体改善或 runtime 采用结论。

若继续，应把引用定位可靠性作为单独问题处理并验证，保持语义准则不变，再在新授权
和独立记录下恢复迁移检查。不能把本次无效记录倒改为成功，也不继续追加语义规则。

当前原提示此前完整评过的题对仍为 P01–P04、D02、D05 六组；本轮只增加了 D06-A
的一份有效原提示报告，不能把 D06 计作完整评过。全部人工材料仍为 16 组题对记录，
其中 13 组明确偏好，没有产生新人工标签。

  无模型预检也通过，确认只有模板变化、system/schema 不变。LSP 未确认 clean，

  此后所有冻结哈希保持不变，prompt 差异恰好是新增准则。
