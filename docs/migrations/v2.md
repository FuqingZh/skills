# Upgrade from v1.0.0 to v2.0.0

v2.0.0 adds `plainspoken` and `dissect`, replaces the long global instruction
block with three skill routes, removes superseded reference paths, and retires
the historical writable-agent evaluation runtime. Review local skill edits,
custom instruction dependencies, and external links before upgrading.

## Install skills, then refresh global instructions

Select only clients you use; the examples select Codex, Pi, and Grok Build.
Repeated `skills add` can overwrite installed edits. With the tested skills CLI
1.7.6 syntax, pin the release explicitly:

```bash
skills add FuqingZh/skills#v2.0.0 -g -a codex pi grok -y
```

Check your installed CLI's help if its syntax differs. An installation pinned
to v1.0.0 does not advance to v2.0.0 through `skills update` alone.
Confirm that all six skills are available through `skills list -g` before
refreshing instructions. The installer does not install or verify skills.

Use a trusted checkout of the same release. A separate directory avoids moving
an existing checkout that may still own legacy links:

```bash
git clone --branch v2.0.0 https://github.com/FuqingZh/skills.git skills-v2
cd skills-v2
./install.sh --agent all --dry-run
./install.sh --agent all
```

Review the preview before applying it. Linux/WSL, Bash, and GNU utilities remain
required; macOS and native Windows installation are unvalidated. For custom
homes, backups, and rejection conditions, use the
[installation reference](../installation.md). Do not add `--force` to bypass
malformed markers or symlinks. An unmarked Codex regular file has a separate
[backup-first migration](skills-cli.md#unmarked-codex-instructions).

The refreshed managed block routes substantive responses to `plainspoken`,
in-depth analysis to `dissect`, and matching engineering work to `calibration`.
The old instructions are retained in the installer's backup when changed.
Any personal rule still needed must be maintained outside the managed block.

## Private host rules are no longer discovered

v1.0.0 rendered a private `calibration/AGENTS.md` path from the host configuration
root into global instructions. v2.0.0 neither discovers nor renders that path.
Private files are not deleted, but the old managed instruction to consult them
is removed when the block is refreshed.

If your work depends on private host rules, explicitly maintain their routing
in your private, block-external instructions or owning repository. The public
package supplies no replacement host-profile discovery. Existing block-external
sections, such as personal continuity or tool-use rules, are preserved.

## Retired runtime and retained evidence

The historical `scripts/run_writable_agent_eval.py` and
`scripts/run_progressive_validation_selection_eval.py` entrypoints are removed.
They are not needed by the skill installer. Their code and dedicated tests were
archived as text at tag `v2.0.0`
(`evaluations/archive/writable-agent-runtime/README.md`),
with hashes and independent evidence checks preserved in Git history.

There is no supported v2 execution replacement. Do not treat archived `.py.txt`
files as maintained tools or their old environment failures as repaired.
Restoring historical execution needs its own environment and support decision.
Other writing and OpenEvals tools were not retired by this change.

## Rollback

Use explicit `skills add FuqingZh/skills#v1.0.0` with your selected clients to
restore the four v1 skills, reviewing local edits before replacement. Downgrading
those skills does not necessarily remove the new `plainspoken` and `dissect`
installations; inspect shared discovery before any explicit removal.

Refresh global instructions separately from a trusted v1.0.0 checkout, previewing
its behavior first. That restores v1's routing, including private host-profile
references, and backs up changed instructions. Personal block-external content
still needs review. Never move a published tag or overwrite the only backup.

For pre-v1 checkout-owned links and the repository rename, see the
[earlier migration guide](skills-cli.md). Neither upgrade nor rollback runs
legacy cleanup automatically, migrates personal learning data, or restores an
unsupported evaluator environment.
