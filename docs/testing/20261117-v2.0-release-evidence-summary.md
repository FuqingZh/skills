# Release evidence: v1.0.0 to the v2.0 candidate

Status: pre-release evidence summary, 2026-11-17. No release is created by this
report. Repository measurements compare published `v1.0.0`
(`b25d812682063a28965af53654c0cf985dd7477c`) with reviewed `main` at
`a08ee73d74acd20053e7310c4bed9d96fcb7ef72`.

## What improved

The candidate has a smaller instruction surface and two additional first-party
skills. A six-task writing pilot also obtained four explicit relative preferences
for its candidate. These are separate results: **there is no measured overall
quality improvement for the final six-skill package versus v1.0.0**.

| Evidence | Observed result | What it supports |
| --- | --- | --- |
| Global routing template | 4,706 → 186 bytes, −96.0% | Much less text in the shared template; detailed instructions now live in skills. |
| Calibration reference Markdown | 39 → 25 files; 76,057 → 41,733 bytes, −45.1% | A smaller reference collection after consolidation, removal, and archival. |
| All first-party skill Markdown | 45 → 35 files; 93,490 → 65,184 bytes, −30.3% | Less packaged Markdown despite expanding from four to six skills. |
| Writing pilot 1 human feedback | Four explicit overall relative choices among six pairs, all favoring the candidate | Positive task-local preference evidence for that frozen writing addition. |
| Current repository CI | 591 tests passed, no skips; maintained Python tools at 100% line coverage | The reviewed package passed its engineering gate. This is not an answer-quality score. |

File sizes count UTF-8 bytes in Git blobs, not model tokens. The Markdown inventory
includes `SKILL.md` and `.md` references under `skills/`; it excludes JSON cases,
YAML metadata, archives outside that tree, and external skills. Reference counts
cover only `skills/calibration/references/**/*.md`. The old template is
`codex/AGENTS.md.template`; the new one is `templates/AGENTS.md.template`.
These inventories overlap and must not be added together.

Instructions moved out of the global template can still be loaded for relevant
tasks. No actual context-token, latency, billing, or workflow-productivity saving
has been measured for the final package. Removed compatibility paths and retired
capabilities also contribute to the smaller surface; see the
[changelog](../../CHANGELOG.md) for migration consequences.

## Where human feedback found better writing

[Writing pilot 1](../../evaluations/communication-style/preference-calibration/writing-pilot-1/README.md)
compared the then-current expression paragraph with the same paragraph plus three
writing paragraphs. Its frozen candidate is not the final `plainspoken` skill.
It used six already-seen tasks, one answer per arm per task, Pi 1.5.0 and
`openai/gpt-6-sol` with high thinking: 12 isolated generations in total.

| Task | Human feedback | Interpretation |
| --- | --- | --- |
| D05: resources and effort | Baseline's closing generalization was unnecessary. | Candidate relatively preferred for relevance. |
| D06: canceled meeting | Baseline's final suggestion felt affected; candidate was more direct. | Candidate relatively preferred for tone and directness. |
| P02: lid and evaporation | Candidate was clearly better: detailed, easier to follow, without affected colloquial or mechanical academic phrasing. | The clearest positive feedback on explanation and progression in this pilot. |
| D03: environment and responsibility | Both were poor; baseline was worse. Both shifted focus awkwardly. | Relative preference for candidate, not acceptance of either answer. |
| D02: p-values | Both added unwanted corrections and qualifications. | Both criticized; no relative choice. |
| P03: electricity use | Baseline presented time, units, and arithmetic more clearly; candidate stated the full-power condition. | A dimensional trade-off; no overall winner inferred. |

The [raw feedback](../../evaluations/communication-style/preference-calibration/writing-pilot-1/feedback-1.json)
and [A/B mapping](../../evaluations/communication-style/preference-calibration/writing-pilot-1/packet-mapping.json)
retain the choices and their source identities. The author had already shown an
initial reading, and mappings were inspectable; this was not a strictly blinded
or independent evaluation. Four favorable choices do not establish a 100% win
rate, general acceptability, factual correctness, or reliable reproduction.

The [second pilot](../../evaluations/communication-style/preference-calibration/writing-pilot-2-isolated/README.md)
tested a different, shorter two-paragraph addition in another 12 isolated
generations. P02 favored the addition, while S02/S03 favored the baseline on
fluency or progression without an overall winner. S01 found both acceptable;
D03/P03 reported little difference without confirming acceptability.
**This batch showed no consistent advantage.** Its
[feedback](../../evaluations/communication-style/preference-calibration/writing-pilot-2-isolated/feedback-1.json)
remains separate; repeated tasks and different prompts must not be pooled into a
single win rate. Local rewrite approvals are also separate from controlled pairs.

### Example: explaining a lid's effect on evaporation

The original question and both complete answers below come from
[pilot 1's public packet](../../evaluations/communication-style/preference-calibration/writing-pilot-1/packet.md#p02).
A is the baseline; B is the candidate. The Chinese text is unchanged. This
illustrates the user's preference for explanation and progression; it is not an
independent physics assessment or an output from the final skill.

Question:

> 为什么盖上盖子通常能让热水凉得慢一些？我知道蒸发会带走热量，但没想明白盖子怎样影响蒸发。

Baseline (A):

> 盖上盖子后，水面上方的空气不容易与外界交换。水蒸气积聚起来，逐渐接近饱和；这时仍有水分子从水面蒸发，也有水蒸气回到水中，**净蒸发量就变小了**。敞口时，空气流动会不断带走水蒸气，让蒸发持续得更快。
>
> 蒸发减少，水带走的热量就少了。盖子还会阻挡水面上方的空气流动，减少对流散热，所以热水通常凉得更慢。

Candidate (B):

> 盖上盖子后，水面上方会留住一小层空气。水继续蒸发，这层空气里的水蒸气很快增多；空气越接近饱和，水面蒸发出去的水分子就越难持续散走，**净蒸发量会下降**。敞口时，空气流动不断带走水蒸气、换来较干的空气，蒸发便能持续得更快。
>
> 蒸发少了，随水蒸气带走的热量就少了。盖子也挡住水面上方的空气流动，减少另一部分散热。热水仍会通过杯壁和盖子散热，所以只是通常凉得更慢；盖子若有大缝，效果也会减弱。

The user's feedback was: “b 明显更好，讲解比 a 细致，同时没有故作俗语，但句式不是哪种论文机械句式，整体论述衔接比较易懂”.
The candidate is longer here. Its positive feedback therefore supports readable
explanation rather than a blanket preference for shorter answers. The original
author reading had penalized a missing microphysical detail; the subsequent
human feedback corrected that interpretation. Both records remain available.

## Other comparisons and unsuccessful attempts

These studies evaluate historical prompts or judges, not the final installed
skills. Their original adoption decisions and failures remain unchanged.
Model ratings are predictions under each study's rubric, not human ground truth.

| Study | Scope | Result and limit |
| --- | --- | --- |
| [Initial style comparison](../../evaluations/communication-style/results.md) | 36 generations; three arms, six development tasks, two repetitions; six judge calls | Zero target-style findings in every arm. Neither candidate met the improvement gate; planned holdout generation did not run. |
| [Full talk-normal](../../evaluations/communication-style/talk-normal/results.md) | 48 generations; 12 tasks, two arms, two repetitions; 12 judge calls | Visible characters −20.4%; rubric omissions 2/88 in both arms. Style findings remained zero/zero. Total reported tokens increased 45.4%; estimated generation cost was essentially unchanged. Not adopted. |
| [Cross-domain paragraph](../../evaluations/communication-style/cross-domain/results.md) | 32 generations; eight tasks, two arms, two repetitions; eight judge calls plus three controls | Omissions 0/60 in both arms; style findings zero/zero. Candidate characters +14.7% and estimated generation cost +12.0%. No demonstrated style gain; not adopted. |
| [Sentence deletion](../../evaluations/communication-style/sentence-ablation/results.md) | 160 generations; 17 comparison attempts including one declared retry; three controls | One original comparison and its retry failed literal-evidence validation. No full-study estimate. The post-hoc seven-task subset favored full over minimal by 1.40 points on its 0–100 index, unadjusted 95% interval [0.30, 2.72]; missing-task selection and near-ceiling scores preclude a general gain or sentence-weight claim. |
| [Preference judge v3](../../evaluations/communication-style/preference-calibration/results-v3.md) | 24 valid outputs; seven primary human-labeled style pairs, each in both orders | Four stable matches, one stable mismatch, two order conflicts. Conflicts stay in the denominator. Judge not selected. |
| [Preference judge v4](../../evaluations/communication-style/preference-calibration/results-v4.md) | 24 attempts; five valid and 19 invalid outputs | All seven primary pairs lack a valid two-order result. Agreement is unavailable, not 0%. Output-contract mismatch retained; no repair or retry. |

The first three style studies used Pi 1.5.0, `openai/gpt-6-astra` with high
thinking for generation, and `openai/gpt-6-sol` with high thinking for judging.
They used isolated instructions, constructed tasks, and a same-provider/model-family
judge. Each linked protocol owns the exact prompts, repetitions, controls,
execution environment, usage estimates, and limitations. These are distinct
experiments with different rubrics and observed task histories; their scores
cannot be combined into one release-wide effect size.

The [Promptfoo replay](../../evaluations/communication-style/preference-calibration/evaluation-tools.md)
organized 48 saved judge outputs: 29 valid artifacts and 19 retained errors,
with zero model calls. Its 60.42% artifact-validity rate is not preference
agreement or answer quality. Replaying evidence does not create new samples.

Other public evaluator probes reached similar limits:
[paragraph-ID evidence](../../evaluations/communication-style/preference-calibration/openevals-contribution-v1-id-evidence/README.md)
produced four traceable reports without resolving the tested human-preference
mismatch; a [Grok configuration comparison](../../evaluations/communication-style/preference-calibration/openevals-model-comparison-3/README.md)
completed eight reports without supporting a model replacement. Earlier
[Claude](../../evaluations/communication-style/preference-calibration/openevals-model-comparison-1/README.md)
and [Gemini](../../evaluations/communication-style/preference-calibration/openevals-model-comparison-2/README.md)
configuration trials stopped on access/completion failures. Those failures are
not model-quality scores, and unavailable failed-call costs are not zero.

## Engineering validation and support scope

[PR #87 CI](https://github.com/FuqingZh/skills/actions/runs/44009716043) and
[post-merge main CI](https://github.com/FuqingZh/skills/actions/runs/44009986484)
passed. At the measured main commit, the gate reported 591 tests, 325 maintained
Python-tool statements with 100% line coverage, and validation of six skills.
It also ran Ruff, formatting, Pyright, Markdown/link checks, ShellCheck, and an
isolated installer preview. Codex review reported no findings on the PR head.
These checks do not execute a new model comparison.

The smaller test count after runtime retirement is not a performance improvement:
309 dedicated historical executor cases were retired with their unsupported
entrypoints; six independent evidence checks were added. All 20 retired source
files remain byte-preserved in the
[runtime archive](../../evaluations/archive/writable-agent-runtime/README.md).
Their environment compatibility failures were retired, not repaired. Required
coverage thresholds and CI protections were not lowered.

## Reproduce the repository measurements

These commands inspect committed objects and make no model calls:

```bash
baseline=v1.0.0
candidate=a08ee73d74acd20053e7310c4bed9d96fcb7ef72
git cat-file -s "$baseline:codex/AGENTS.md.template"
git cat-file -s "$candidate:templates/AGENTS.md.template"
for ref in "$baseline" "$candidate"; do
  printf '%s\n' "$ref"
  git ls-tree -rl "$ref" -- skills/calibration/references |
    awk '$NF ~ /\.md$/ {n++; b+=$4} END {print "reference Markdown files/bytes:", n, b}'
  git ls-tree -rl "$ref" -- skills |
    awk '$NF ~ /\.md$/ {n++; b+=$4} END {print "all skill Markdown files/bytes:", n, b}'
done
```

Percentage reduction is `100 × (baseline − candidate) / baseline`, rounded to one
decimal place. The linked studies provide their own offline summary and test
entrypoints. Original outputs, human labels, hashes, failed attempts, and frozen
protocols are unchanged by this report. Only already-public evidence is included;
private studies and unopened holdout material are not used for release claims.

## What remains unmeasured

- Final English `plainspoken`/`dissect` instructions against the v1.0.0 package,
  including native skill selection and the full installed instruction stack.
- Reliable reproduction across repeated runs, clients, model families, domains,
  and long evolving conversations.
- General human preference, preserved learning value, fewer factual errors,
  reduced cost, or improved end-to-end task completion time.

A future release-wide quality claim needs a separately authorized, frozen
baseline/candidate comparison on representative fresh tasks, with human
preferences and content regressions reported together. This report authorizes
neither new calls nor a release. The supported release message is **smaller,
more clearly separated guidance, with encouraging local writing feedback and
explicitly unresolved generalization**.
